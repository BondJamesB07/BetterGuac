Servers

Editing servers in the list

  • Each row is one server. Change the name, type, host, port or username right in the row.
  • Fill in the empty row at the bottom and press the green + (or Enter). The server joins the list and a new empty row opens, so you can keep adding.
  • The red × marks a server for deletion. It turns grey and crossed out until you save, and Undo brings it back.
  • The pencil opens every setting for that server, like domain, security mode and certificates.
  • Test checks one server from the BetterGuac server's network, using the type and port in its row, even before you save. The dot turns green when it answers (an SSH or VNC greeting, an RDP handshake, or an open port for Telnet and Kubernetes) and red when it doesn't, with the reason under the row. Test all servers tests every server shown.
  • After Test all servers, a popup lists the servers that didn't answer, with the reason for each. Click a name to jump to its row, test one again, or show only the failed servers in the list. The red button at the top of the page opens the popup again.
  • Password: leave it empty to keep the saved password. Type one only to set or change it.
  • Key file (SSH only): the full path to the server's private key file on the BetterGuac server, like /etc/betterguac/keys/web-01. Don't paste the key itself. Key files go in /etc/betterguac/keys, owned by root with group tomcat and mode 640, so Guacamole can read them but other accounts can't: sudo install -o root -g tomcat -m 640 web-01 /etc/betterguac/keys/. The key is read from the file each time someone opens the server, so it never goes into the database or the browser. Both OpenSSH and PEM (RSA, EC) keys work. If the key has a passphrase, set it with the pencil. Test also checks the key file and says what's wrong with it.
  • Port: leave it empty for the usual port of that type (SSH 22, RDP 3389, VNC 5900, Telnet 23, Kubernetes 8080).
  • Groups: type one or more group names, separated by commas, like Proxmox, database. A new name creates the group. A user who's a member of any of a server's groups can open that server. You give users their groups on each user's page.
  • Manage groups lists every group, empty ones too. Deleting a group keeps its servers and takes away the access it gave its members.
  • The search box and the group buttons above the list only narrow down what you see. No group shows servers that aren't in any group.
  • Nothing is changed on the server until you press Save changes. Deleting asks you to confirm first. Discard throws away everything you haven't saved.
  • Row colors: green edge is new, blue edge is changed, red means something needs fixing.
  • The empty row keeps the type and groups you used last, so adding several servers to one group is quick.

Add or update many servers at once

How it works: paste your list, press Verify to see each line in a table, then press Apply. The good lines fill in the rows in the list above. Then press Save changes to keep them.

Connectivity: Verify also tests every good line from the BetterGuac server itself, with that line's type and port. A green dot means the server answered: an SSH or VNC greeting, or an RDP handshake. For Telnet and Kubernetes only the port is checked. A red dot means it didn't, and the reason is next to it. A red dot doesn't stop you from applying the line.

Format: one server per line, columns in this order:

name, type, host, port, username, key file, groups
  • name: required. If a server with that name is already in the list, the line updates it instead of adding a new one.
  • type: required. ssh, rdp, vnc, telnet or kubernetes. Upper or lower case both work.
  • host: required. Host name or IP address, no spaces. You can write host:port here instead of using the port column.
  • port: optional. 1 to 65535. Empty means the usual port for that type.
  • username: optional.
  • key file: optional, SSH only. The full path to the private key file on the BetterGuac server, like /etc/betterguac/keys/web-01. It must start with /; anything else in this column is read as a group, so lists written before key files still work. Never paste the key itself here. Verify checks that the file is there and Guacamole can read it.
  • groups: optional. With commas, every column after the key file (or after the username, when there's no key file) is a group, so ..., admin, Proxmox, database puts the server in both. With tabs, put the groups in one cell separated by commas or semicolons. With tabs, the key file is the 6th column and groups the 7th. To give groups but no port or username, leave those columns empty: NAS, ssh, 192.0.2.5, , , storage.
  • Separate columns with commas or tabs, so a copy from a spreadsheet works. A first line starting with "name" is treated as a header and skipped, and lines starting with # are ignored.
  • For a server that's already in the list, an empty port, username, key file or groups column leaves its current value. Groups you do give replace its current groups.
  • Passwords aren't taken here, so they don't sit in plain text. Type them in the list above.
  • Lines with a problem are shown in red with the reason and are left in the box after Apply, so you can fix them.

Example:

name, type, host, port, username, key file, groups
Web-01, ssh, 192.0.2.50, 22, admin, /etc/betterguac/keys/web-01, web
PVE-1, ssh, 192.0.2.10, 22, root, /etc/betterguac/keys/pve, Proxmox, database
NAS, ssh, 192.0.2.5, 22, user, , storage
Desk-PC, rdp, 192.0.2.60:3389, user
Lab-Switch, telnet, 192.0.2.2
